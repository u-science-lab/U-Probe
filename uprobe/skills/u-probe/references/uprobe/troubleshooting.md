# Troubleshooting U-Probe runs

Read this when `uprobe validate` or `uprobe run` fails, a run ends with no or too few probes, or the
result looks wrong (strand, overlaps, off-targets). Each entry: **symptom**, **cause**, **fix**.
Start every diagnosis from the exit code and `summary.json` (`status`, `message`, `stopped_at`,
`error`, `warnings`, `targets.<t>.after_stage`, `top_removal_stage`); see `references/uprobe/workflow.md`.

## Triage by status

| Exit / `status` | Look at | Usual cause |
| --- | --- | --- |
| 2, no summary | the command line | missing `-p`/`-g`, a path that does not exist |
| 1 `error`, `stopped_at: load_inputs` or `normalize_protocol` | `error` | protocol rejected (run `uprobe validate`), genome name not in `genomes.yaml`, FASTA/GTF path missing |
| 1 `error`, `stopped_at: validate_targets` | `error`, `inputs.invalid_targets` | a target is not a GTF `gene_name` and `--continue-invalid` was not given |
| 1 `error`, `stopped_at: build_index` | stderr log | aligner not installed, unreadable FASTA, disk space |
| 1 `error`, later steps | `error` | aligner missing at alignment time, transcript selection, expression table |
| 3 `no_valid_targets` | `inputs.invalid_targets` | no target name is a GTF `gene_name` (with `--continue-invalid`) |
| 3 `no_target_sequences` | `warnings: no_candidate_windows`, log | no window fits any target's segments (below) |
| 3 `no_probes_constructed` | `warnings: probe_construction_failed` | an expression fails for every candidate |
| 3 `no_probes` | `stages`, raw table | filters removed everything |
| 0 `partial` | `warnings`, per-target `final` | some targets short or empty |

## Validation errors

- **Symptom:** `uprobe validate` exits 1. **Cause:** schema, expression, column or genome problems.
  **Fix:** apply each `fix:` line; rerun until `OK`. Errors that `validate` catches but `run` would
  **ignore silently**: misspelled `post_process` step (e.g. `remove_overlaps`), filter or sort on an
  unknown column, `or`/`|` or text after a number in a condition. Always validate after editing.
- **Symptom:** `condition` rejected or misread. **Cause:** only `<column> <op> <number>` joined by `&`;
  a signed number is fine (`dg37 >= -36`), scientific notation and `or` are not. **Fix:** split into several
  filters; write `0.00001` not `1e-5`; `fold_score` is >= 0, so `target_fold <= 5`, never `>= -5`.
- **Symptom:** `validate` warns `tm_method merfish_design (or oligominer) uses ...; ... not declared`, or
  `does not use ...`. **Cause:** a design code's formula reads only some conditions; one it reads is not
  declared (it then runs at the legacy PCR defaults, e.g. 64.9 instead of 42.9 °C for an OligoMiner example
  probe), or the attribute's override declares one it ignores. **Fix:** give the attribute the published
  window's conditions as its override (`hybridization: {na_mM: 300, probe_nM: 5}` for MERFISH, `{na_mM: 390,
  probe_nM: 25, formamide_pct: 50}` for OligoMiner) and nothing else.
- **Symptom:** `validate` warns that `rna_dna_dg37` on `target_region` reads it as the probe. **Cause:**
  `target_region` is the RNA sense sequence; with `sequence: probe` (the default) the value is that of the
  other strand (up to 8.8 kcal/mol off). **Fix:** put the attribute on the probe's binding part, or keep
  `target_region` with `sequence: target`.
- **Symptom:** `validate` warns `... is sorted descending, which ranks the most structured candidates
  first`; or the top-ranked probes have the highest `_fold`, `_self_match` or `_kmer_count`.
  **Cause:** lower is better for these scores (`fold_score` is -MFE), but protocols that kept the
  defaults generated by older U-Probe versions, or copied the old `double_hyb_rca` template, sort them
  in `is_descending`. **Fix:** move them to `is_ascending`.
- **Symptom:** `unknown name 'gene'` / `'ACGT'` in an expression. **Fix:** the target name is `target`;
  quote literals inside the YAML string: `expr: "'ACGT'"`; constant parts can also be
  `{template: "ACGT", parts: {}}`.

## Genome, indexes and aligners

- **Symptom:** `AssertionError: bowtie must be enabled in genome align_index` (or `bowtie2`,
  `Jellyfish must be enabled`). **Cause:** an attribute needs an index the genome entry does not list.
  **Fix:** add `bowtie`/`bowtie2` to `align_index` or set `jellyfish: true` (or `locus_only: true` on the
  `kmer_count` attribute, which needs no genome-wide table); `uprobe build-index`.
- **Symptom:** run fails with `FileNotFoundError` naming `bowtie-build` (at `build_index`) or `bowtie`
  (at the attributes), or `validate -g` warns `bowtie-build and bowtie not found on PATH`. **Cause:** Bowtie 1 not installed (it is a separate
  package from Bowtie2). **Fix:** `conda install -c bioconda bowtie`; check `which bowtie bowtie-build`.
- **Symptom:** log says `Auto-generated target_mapped_genes: aligner bowtie2, because ...` and the
  off-target filter removes nothing on 18-21-nt windows. **Cause:** Bowtie 1 or the `bowtie` entry is
  missing, so the generated attribute fell back to Bowtie2, whose local mode cannot align < 22 nt
  (every window counts 0 genes). **Fix:** install Bowtie 1, add `bowtie` to `align_index`, or write the
  attribute with `aligner: bowtie`. Never deliver short probes checked only by Bowtie2.
- **Symptom:** first run takes long at `build_index`. **Cause:** a missing index that an attribute
  searches is built first, e.g. the Bowtie2 genome index for `mapped_sites` (DNA FISH; hours for a
  mammalian genome). Indexes no attribute searches are not built. **Fix:** build once with
  `uprobe build-index -p protocol.yaml -g genomes.yaml -t <cores>` before designing.
- **Symptom:** index build fails immediately / "does not contain a valid sequence". **Cause:**
  gzipped or truncated FASTA, a Git LFS pointer file, or a broken aligner binary. **Fix:** `head` the
  FASTA (must start with `>`); run `bowtie-build`/`bowtie2-build` by hand on a small FASTA.
- **Symptom:** a run spends long at the first `kmer_count` after a new `kmer_len`. **Cause:** each k-mer
  length has its own Jellyfish index, `jf_genome/<stem>.k<kmer_len>.jf` (`.stranded.jf` with `strand:
  sense` or `antisense`), built when first needed (an index left by older versions, `jf_genome/<stem>.jf`,
  is reused only if its header has the same k).
  **Fix:** for a locus-sized target set `locus_only: true` on the attribute: one pass over the genome counts
  only the candidates' k-mers (about a minute for human, a few MB). For genome-wide tables keep one
  `kmer_len` per genome to build once, and delete indexes you no longer use.
- **Symptom:** `kmer_count` with `locus_only` fails in `jellyfish count`, or `validate` warns `jellyfish is
  not on PATH`. **Cause:** no Jellyfish, or Jellyfish 1.x, which has no `--if`. **Fix:** install Jellyfish 2
  (`conda install -c bioconda kmer-jellyfish`; `jellyfish --version` prints 2.x).
- **Symptom:** `validate`, the run or `genome add --existing-index` stops on an index under `indexes:` whose
  records are not named `<gene_id>_<transcript_id>` (e.g. `ENST01.1 -> gene 'ENST01.1'`). **Cause:** a
  transcriptome index built from a plain transcript FASTA: `mapped_genes` reads each hit's gene from the record
  name, so the target's own isoforms would count as off-target genes. **Fix:** build it from U-Probe's
  `transcript.fa` (`bowtie-build <index_dir>/transcript.fa <prefix>`), or drop the key and let the run build
  it. Without `bowtie-inspect`/`bowtie2-inspect` on `PATH` the names are not checked (a warning).
- **Symptom:** `genome add` warns that FASTA records are not in the records table. **Cause:** they are left
  out of the annotation and of the off-target index, so their genes can never count as off-targets.
  **Fix:** list every transcript in the table, or `--unlisted include` (each becomes a gene of its own).

## Targets and transcripts

- **Symptom:** run stops at `validate_targets` with `N target(s) not found in the genome annotation`,
  or an `invalid_targets` warning or `no_valid_targets`. **Cause:** names are matched against
  GTF `gene_name`, case-sensitively (`GAPDH` human, `Gapdh` mouse); gene ids and old aliases do not
  match; genes without a `gene_name` cannot be named. **Fix:** `validate --check-targets` suggests the
  closest name; look the gene up in the GTF; for an unnamed gene use a literal sequence target named
  after its gene id. Without `--continue-invalid`, any invalid target stops the run (exit 1) before
  indexes are built or anything is designed; with it, invalid targets are skipped and listed
  (`partial`, or `no_valid_targets` with exit 3 when none is left). Web-server tasks always skip them.
- **Symptom:** `no transcript of X is tagged MANE_Select or Ensembl_canonical`. **Cause:** non-Ensembl
  GTF (RefSeq, custom), or an old release without tags. **Fix:** list transcript ids
  (`transcripts: [ENST...]`), or `transcripts: all`; MANE exists only for human.
- **Symptom:** a target has `candidate_windows: 0` (warning `no_candidate_windows`; status
  `no_target_sequences` if no target has any) and the log says `Gene X: all its N ... segment(s) are
  shorter than the ...-nt window`. **Cause:** with `exon`/`CDS`/`UTR` and `transcripts: all`, segments
  shorter than `length` are dropped, and that target had none left; the other targets are designed.
  **Fix:** use a single transcript (`transcripts: mane`/`canonical`/list: spliced tiling, no length
  filter; not for `UTR`) or `source: mRNA`, or shorten the window.
- **Symptom:** a target gets no windows with `source: UTR`. **Cause:** no UTR features (non-coding
  gene, or a GTF without UTR lines). **Fix:** `source: mRNA`.

## Too few probes

**Report the shortfall first.** The run that follows the method's published rules (its length, GC, Tm,
spacing, the sample's expression table with `min_fraction_of_target` and `exempt_copies`) is the result;
write down probes vs requested and `top_removal_stage`, and deliver that set with the shortfall if nothing
below is justified. Then read `targets.<t>.after_stage` and `top_removal_stage`, change one thing per run,
report the yield of each change, and do not fill the count with a different length:

| Stage that removed most | Likely cause | Fix (keep the method's specificity rule) |
| --- | --- | --- |
| `Filters` (off-target) | processed pseudogenes/retrocopies that copy the target; paralogs sharing the CDS; unexpressed genes counted | `exempt_copies: true` (copies only; paralogs stay counted); `gene_expression` with your sample's table (+ `min_fraction_of_target: 0.05`); `source: mRNA` (UTRs diverge more than CDS); see `references/concepts/specificity.md` |
| `Filters` (Tm/GC) | window computed under other conditions or formula, or too narrow for the region's GC | check `inputs.hybridization_conditions`; formamide entry below; reproduce the published window under its own conditions and formula (`tm_method`); do not stretch it, and do not change lengths set by the method |
| `Remove overlap` | short target: few non-overlapping sites; repeats; first-fit packing | lower `location_interval` to the method's smallest published value (smFISH: 3 nt Raj, 2 nt Stellaris), longer region (`mRNA` not `CDS`), amplified methods for very short RNAs (`references/concepts/targets-and-isoforms.md`); the repeat and packing entries below |
| `Off-target pool limit` | many probes share one off-target gene | expected; it trades count for cleanliness |
| `Equal spacing` | never below the request | the shortfall is upstream |

Count which filter fails: rerun with `--raw`, load `*_raw.xlsx` (`pandas.read_excel`) and evaluate each
condition separately per target.

### Length ranges are not a way to fill the count

`length: [min, max]` makes a window of every length at every start, and `remove_overlap` keeps the
shortest passing one per start. With a range around the standard length (`[18, 22]` for a 20-nt method)
most of the set therefore leaves the standard length (18-mers where 18 passes, 22-mers only where
shorter ones fail), which is a different set from the published one, not a rescue. Keep the standard
length wherever it passes and take another length only at the sites where it fails, by ranking
the windows of each start by their distance to the standard length with `remove_overlap.prefer`
(an attribute, lower is better; the stand-in probe only supplies the reference length):

```yaml
name: standard_length_first
genome: hg38
targets: [GAPDH]
encoding: {GAPDH: {}}
extracts:
  target_region: {source: mRNA, transcripts: mane, length: [18, 22], step: 1}
probes:
  smfish_probe:
    template: "{binding}"
    parts:
      binding: {expr: "rc(target_region)"}
  standard_20:                       # not ordered: a 20-nt stand-in whose length is the reference
    template: "{ref}"
    parts: {ref: {template: "AAAAAAAAAAAAAAAAAAAA", parts: {}}}
hybridization: {temperature_c: 37, na_mM: 390, formamide_pct: 10, probe_nM: 2.6, dntp_mM: 0}
attributes:
  probe_len: {target: smfish_probe.binding, type: length}
  standard_len: {target: standard_20, type: length}
  len_off: {type: difference, of: [probe_len, standard_len]}   # |length - 20|, lower is better
  probe_tm: {target: smfish_probe.binding, type: annealing_temperature}
  target_mapped_genes: {target: target_region, type: mapped_genes, aligner: bowtie, max_mismatches: 2, strand: sense}
post_process:
  filters:
    target_mapped_genes: {condition: target_mapped_genes <= 1}
    probe_tm: {condition: probe_tm >= 37}
  remove_overlap: {location_interval: 3, prefer: len_off}   # of one start's windows, the one nearest 20 nt
  equal_space: {number_desired: 48}
summary: {report_name: rna_report, attributes: [probe_len, probe_tm, target_mapped_genes]}
```

With only longer alternatives, `length: [20, 22]` needs no `prefer`: the shortest, 20 nt, wins wherever it
passes. Either way the other lengths must lie inside the method's published range, and the final table's
length distribution (`probe_len` counts) goes into the report; the standard-length set stays the
reference to compare the yield against. `prefer` chooses between lengths of the same start only; it does
not move starts (see "Overlapping or clustered probes").

### Repeats inside the target

- **Symptom:** warning `multi_site_oligos`; rows with `n_sites` > 1 and `oligo_sites`; fewer probes than the
  target's length suggests. **Cause:** a target with tandem or internal repeats (tandem-repeat genes,
  repeated domains) contains the same window at several positions, and one oligo binds every copy. U-Probe
  counts such an oligo once: `remove_overlap` keeps it only where none of its sites is within
  `location_interval` of a kept one, then all its sites are occupied; `equal_space` ranks it once.
  **Fix:** nothing to undo. Report the multi-site oligos (they carry more signal per probe) and count
  distinct oligos (`check_probes.py --min-probes`; `--min-gap` uses `oligo_sites` or every site on the
  transcript). If the distinct set is short, report it before adding anything. A table made by an older
  U-Probe (identical rows, no `n_sites`) must be deduplicated by sequence and checked over all sites
  (`check_probes.py --transcripts ... --min-gap`).


## Formamide makes Tm filters remove everything

- **Symptom:** `stage_removed_all` at `Filters`; the Tm attribute's median is far below the window.
- **Cause:** a published Tm window (often computed at 0% formamide, e.g. MERFISH 66-76 °C at 300 mM
  Na+) applied to Tm computed under the protocol's `hybridization` block with formamide. Primer3 lowers
  Tm by about 0.6-0.7 °C per % formamide (`references/concepts/hybridization-and-tm.md`): a 20-mer at 45% GC
  computes about 60 °C in 2x SSC, 40 °C at 30% formamide, 27 °C at 50%.
- **Fix:** give the Tm attribute the window's own formula and design conditions:
  `tm_method: merfish_design` with `hybridization: {na_mM: 300, probe_nM: 5}` (as the MERFISH template does;
  `oligominer` for OligoMiner's 42-47 °C); or set the window relative to the real hybridization temperature
  under the real conditions. Never shift a window without saying which formula and conditions it refers to.
- Related: auto-generated filters (no `post_process`) put a Tm window [T, T+40] °C on every probe
  *and part*, constant readouts included; one constant part outside it removes every candidate. Write
  `post_process` yourself.

## Wrong strand

- **Symptom:** probes have the same sequence as the mRNA; `target_mapped_genes` is 0 on every row;
  or off-target lists contain antisense transcripts. **Causes and fixes:**
  - Binding part written as `target_region` for an RNA target: it must be `rc(target_region)`
    (`target_region` is the RNA sense sequence, 5'->3'). Exception: padlocks that bind **cDNA**
    (HybISS) carry the RNA-sense sequence in their arms.
  - `mapped_genes` on a binding part (antisense) with `strand: sense`: use `strand: antisense`, or
    better run the attribute on `target_region` with `strand: sense`.
  - `strand: both` (default) also counts transcripts antisense to the target, which the probe cannot
    bind: set `sense` for `target_region`.
- Check: a correct RNA design has `binding == rc(target_region)` and `target_mapped_genes >= 1` on every
  row (the own gene), except literal-sequence targets absent from the annotation.

## Overlapping or clustered probes

- **Symptom:** final probes overlap. **Cause:** `equal_space` without `remove_overlap` picks evenly
  spaced *ranks* of overlapping windows. **Fix:** add `remove_overlap: {location_interval: N}`.
- With `length: [min, max]` or a `layout` with ranges, several candidates share a start; `remove_overlap`
  keeps the first (shortest) passing one, or the lowest of `remove_overlap.prefer` (an attribute, e.g. a
  `difference` of two Tm, or a distance to the standard length, above). Filter lengths you do not want.
- `remove_overlap` is first-fit from the 5' end: it takes a start, then the next start beyond the gap, and never
  looks back, so when the passing pool is barely enough it leaves no alternative for a weak window (a
  half with low GC or Tm sits in the final set because the only other candidates overlap it). It does not choose
  between different starts: put quality into `filters`, and prefer a method's published criteria to extra ones.
  If you must choose among overlapping candidates by an objective (balanced halves, GC nearest a target), rank them
  yourself on the raw table (`--raw`) and verify the pick with `check_probes.py`, instead of adding a filter that
  the method does not publish; compare the yield and the picks with and without any extra filter.
- Probes cluster in one region: the rest of the target failed filters (check positions of the raw
  candidates); `equal_space` spaces by rank among survivors, not by distance.

## Off-target counts look wrong

- 22-30-nt windows with `aligner: bowtie2`: sites are missed (README: Bowtie2 flagged only 69-88% of
  25-30-nt windows with a site within 2 substitutions in another gene). Use `aligner: bowtie`.
- Windows in repeats hit hundreds of genes; Bowtie2 reports at most 100 alignments, so counts saturate.
- Junction windows (one selected transcript): `mapped_sites` and `kmer_count` search the genome, where
  the intron splits the window; judge RNA probes by `mapped_genes`.
- A gene listed in `_copies` is exempt from the count and from `off_target_pool`; read the list before
  delivery (a copy that is a real, expressed gene still produces signal).
- `gene_expression`: `off_target_genes_not_in_expression_table` (genes, or with `level: transcript`
  genes with hit transcripts the table lacks; counted unless `absent: ignore`); a table with no
  matching id stops the run (wrong species, identifiers or annotation release);
  `targets_not_in_expression_table` means `min_fraction_of_target` did not apply to those targets.
- **Symptom:** `validate`: `level is gene, but column ... holds transcript ids` (or the reverse);
  `run`: `none of the ... genes|transcripts of the genome annotation is in <table>`. **Fix:** set `level: transcript` with `transcript_column` (salmon `Name`), or `level: gene`
  with `gene_column`; `gene_column` is rejected with `level: transcript`.
- A transcript table quantified on another annotation release misses new transcript ids (counted
  under `absent: count`); quantify on the genome's GTF, or accept `absent: ignore` knowingly.

## Output files

- **Symptom:** warning `excel_limits` in `summary.json`; an `.xlsx` cell ends with
  `...[truncated: N characters; full value in <name>.tsv]`. **Cause:** an Excel cell holds at most
  32,767 characters; repeat windows can carry longer off-target or site lists (mostly in the raw table
  of `--raw`, or of a run where no probe passes). **Fix:** none needed: read the full value from the
  TSV named in the cell (`_probes.tsv` for the final table, `_raw.tsv` for the raw one; also in
  `output_files`). A `sequence_pattern` or off-target filter keeps such windows out of the final table.
- **Symptom:** no `.xlsx` for a table, warning `excel_limits` with `xlsx: null`. **Cause:** the table
  has more rows than an Excel worksheet holds (1,048,576 with the header). **Fix:** read the TSV
  (`output_files.raw_tsv` / `tsv`), which has every row; or use fewer targets per run or a larger `step`.
- Several result tables in one directory: tables are timestamped; trust `summary.json -> output_files`.
